# 336 台候选设备只读核对（2026-10-03）

来源：`config/devices.operator.json` 中未启用采集的 336 条候选。此前 2026-07-26 的清单为 383 条统一填写端口 6310，文档说明端口尚未逐台现场验证。

从 waveform 服务器对 330 个唯一候选 IP 做 TCP 连接（6310、22，0.8 秒超时、最多 16 并发），再对 6310 未通过的主机及 PV 超时的主机检查 TCP 5064。对 6310 可连的 169 条候选 PV，使用 caproto 做只读连接与读值，最多 8 并发；没有写 PV、触发采集或登录设备。

按设备计：6310 TCP 可连 169 台，超时 165 台，拒绝 2 台；可连的 169 台中 PV 可读 158 台、PV 超时 11 台。所检查的 5064 主机无一可连。当前服务端 `known_hosts.probe47` 对新增 336 台没有受信条目。即使 PV 可读，仍需确认 SSH 主机密钥、登录权限、新 TXT 的位置/格式及实际 20000 点，才能启用采集。

已用当前服务器程序在**本地临时测试数据**上验证 schema v2 可加载 383 台并配置 383 的单次请求上限；测试用主机密钥是合成占位，只用于 `--check`，不在此清单及任何部署包中。它不证明实际 383 台可采集。目前服务器仍运行原 47 台正式注册表，没有修改现场服务。

TCP/CA 连通性是这次检查时刻的快照，超时也可能受网络策略或设备状态影响。逐台结果在 `candidate-336.csv`。

后续对未通过的 161 个唯一 IP 把 TCP 超时延长到 2 秒重试，结果未变；11 个 PV 以 6 秒连接超时重试，仍全部超时。169 台候选的 SSH 服务返回了与现有 47 台受信设备**相同的公钥材料**，但设备使用共享密钥不能单独证明每台主机的身份。指纹在 `ssh-fingerprints-169.csv`，逐台连接候选在 `connection-candidates-169.csv`。

服务端使用密码登录设备。尚未以该密码登录新增主机、检查 `/home/data` 或验证新 TXT 格式；在主机身份经独立确认前，不把候选设备加入运行中的 `known_hosts`，也不启用实际采集。当前服务和两个正式软件包仍为 47 台采集版本。
