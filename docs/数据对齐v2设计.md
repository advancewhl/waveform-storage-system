# 数据对齐 v2 设计基线

> 状态：纯函数、HDF5 v2/legacy 适配器与 GUI 最小接入已完成，尚未做 GUI 点击流或现场验证
> 现场依据：`docs/history/2026-07/线上运行基线调查.md`

## 1. 为什么不能继续使用顺序式 50% 跳过

2025-11-12 12:07:21 的真实批次包含 36 台设备，每台都有 1,024 个非零、唯一、递增的
`uint64` bunchID，但全设备严格交集为 0。

现场数据至少包含：

- 约 30 台设备构成的主覆盖簇；
- 3 台同为 500,000 步长、但窗口完全错开的设备；
- 2 台步长约 75/76 的 L1 冷 BPM；
- 1 台步长为 61/75/76 的 COL0 BPM。

因此，按设备输入顺序逐台求交集并在交集下降时跳过设备，会把输入顺序变成隐式业务规则。
如果先遇到小簇，算法可能保留小簇而排除主簇。

## 2. v2 的边界

本阶段只做可测试的整数 ID 对齐：

- bunchID 始终保存为 `uint64`；
- 不猜测不同设备的缩放、取模或时钟换算；
- X/Y 为 0 是合法数据，通过 `valid_mask` 与缺失值区分；
- 输入乱序会稳定排序；
- 重复 bunchID、长度不一致和无共识都有设备级原因；
- 设备结果按 `device_id` 排序，不依赖输入顺序。

本阶段不做：

- 不替换生产服务器；
- 不重写现有 GUI 或改变采集入口；
- 不定义未经现场确认的物理单位；
- 不把不同步长或不同窗口自动判定为坏设备。

legacy `create_hdf5()` 已改为从输入到 dataset 始终保留 `uint64`，并用过滤后的设备列表写
`Device` 和 X/Y 行属性。回归测试使用约 `3.8×10¹³` 的真实量级 ID，防止整数溢出和元数据错位复发。

## 3. 两种模式

### strict

对所有通过质量检查的设备取精确交集。无交集时返回空的结构化结果和原因，不抛出索引
异常。

### coverage

迭代执行：

1. 选择达到 `min_id_device_coverage` 设备覆盖率的 bunchID；
2. 计算每台设备对候选 bunchID 的覆盖率；
3. 排除低于 `min_device_id_coverage` 的设备并记录原因；
4. 用剩余设备重新计算，直到设备集合稳定。

若两个互不相交的簇规模相同且都达不到阈值，返回“无共识”，不会按输入顺序任选四舍五入
出一个结果。

## 4. 结果结构

```text
AlignmentResult
├─ bunch_ids          uint64
├─ device_ids         稳定排序后的设备 ID
├─ x / y              对齐后的二维数组
├─ valid_mask         区分缺失位置与真实数值 0
├─ skipped_devices    设备、原因和细节
├─ quality_report     零值、重复、顺序、步长等
└─ parameters         本次对齐的显式参数
```

coverage 模式中的缺失 X/Y 单元暂以 0 作为存储占位，使用者必须以 `valid_mask` 判断有效性。

## 5. HDF5 v2 与兼容边界

实现位于 `src/waveform_storage/io/hdf5_io.py`：

- 单 BPM reader 校验 `BunchIDData`/`Data` 形状并保留 `uint64`；
- v2 writer/reader 保存 `bunch_ids`、`x`、`y`、`valid_mask`、`device_ids`、
  `skipped_devices`、`quality_report`、`parameters` 和调用方元数据；
- 文件根属性包含 `schema_name=site-user-waveform-alignment` 和 `schema_version=2`；
- 写入使用同目录 `.part` 临时文件和原子替换；
- legacy writer/reader 保留交错 X/Y 行格式，并验证行数与设备属性映射；
- coverage 结果只要存在缺失单元，legacy writer 就拒绝写入，必须使用 v2 的 `valid_mask`。

## 6. GUI 最小接入与后续条件

现有 GUI 已增加窄适配层：

- 确认、绘图和导出按查询键共享同一个 `AlignmentResult`；
- 绘图使用 `valid_mask`，不会把真实 0 当作缺失；
- 导出支持 `auto/legacy/v2`，`auto` 在有缺失单元时选择 v2；
- 旧 `main_dataprocess()` 和 `create_hdf5()` 保留，未一次性重写 GUI；
- 无共同 bunchID 时返回结构化结果并阻止继续绘图或导出。

进入现场或扩大 GUI 改造前仍需要：

1. 用脱敏真实 fixture 重放现场主簇、错窗簇和异步长簇；
2. 与现场负责人确认覆盖率阈值和不同 bunchID 体系的语义；
3. 用脱敏真实 fixture 对比 legacy 与 v2 的设备选择、ID 数量和耗时；
4. 完成 Linux GUI 点击流及慢网络条件下的验证。
