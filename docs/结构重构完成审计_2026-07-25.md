## 架构与兼容结论

- `apps/operator_gui` 保留 Qt 入口、生成 UI、兼容 facade 和依赖组装；
- `apps/acquisition_agent` 是兼容启动入口；
- RetrievalService 与 CaptureService 不依赖 Qt；
- GuiController 通过构造参数接收检索、对齐、导出和原始下载 action，不依赖具体控件；
- processing 不依赖 Qt、Paramiko 或 ZMQ；
- transport 不修改 Qt 控件；
- `overlap.py` 是兼容 facade，新流程不调用 legacy 对齐算法；
- SSH、HDF5、对齐和导出不在 GUI 主线程执行；
- 当前七个按钮对象名、回调映射和 `mainWindow.ui` 未改变；
- legacy 消息、日期/时刻、远程目录、文件名、导出名和缓存键契约未改变；
- `uint64` bunchID、AlignmentResult、valid_mask、legacy/v2 HDF5 语义未改变；
- 采集原型的 `listdir()[0]`、整数时长相减、1024 点和 `/1000` 行为只保留在 legacy
  adapter，并由字符化测试固定；
- 候选 JSON 只运行本地 `inproc://` fake 闭环，未替换 GUI legacy sender。

与阶段 0 的业务行为差异：无已知业务行为差异。变化集中在职责拆分、后台执行、错误结构、
日志、测试和工程化入口。后台执行改变的是线程位置，不改变按钮业务动作或结果契约。
