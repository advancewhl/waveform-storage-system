## 3. 标识、日期、目录和文件名契约

### 3.1 设备 ID

- 规范 ID 使用大写字母、数字和下划线，注册表校验式为 `^[A-Z0-9_]+$`。
- 当前 47 台的形态为 `AC_LA_<section>_BI_<device>`，例如
  `AC_LA_INJ1_BI_SBPM08`。
- 当前静态 Qt 控件名由规范 ID 去掉 `AC_LA_` 并把 `_BI_` 折叠为 `_`，例如
  `INJ1_SBPM08`。
- 设备顺序来自注册表 `order`，当前为连续的 `0..46`。
- 当前注册表共 47 台启用设备，12 台 `acquisition_enabled` 且默认选中。
- 未知设备不参与新 `AlignmentResult` 路径的对齐，记录为 `unknown_device`；legacy
  `main_dataprocess()` 对未知设备仍可能在 `list.index()` 处失败。

### 3.2 日期与时刻

- GUI 日期来自 `dateEdit`，显示语义为 `YYYY-MM-DD`。
- 查询 `runID` 通过删除日期中的连字符得到 `YYYYMMDD`，例如 `2026-07-25` →
  `20260725`。
- 远程文件时刻字段为 `HHMMSS`；组合框显示为 `HH:MM:SS`。
- `get_para()` 只删除冒号，例如 `12:07:21` → `120721`。
- 当前没有对空字符串、非六位时刻或非法日期进行严格格式校验。

### 3.3 远程目录与文件名

- GUI 查询目录由
  `os.path.join("/SHINE_Data/AC/LA/", runID, "raw/BIData/")` 构造。
- 在生产 Linux 上的目标规则为
  `/SHINE_Data/AC/LA/YYYYMMDD/raw/BIData/`。
- 单 BPM 文件名按
  `RAW-HHMMSS-<device_id>-S<sequence>.h5` 解析；当前正则为
  `RAW-\d+-(.*?)-S\d+\.h5`。
- 时间列表通过查找目录下全部 `*.h5`，再取文件名按 `-` 分割后的第二段，去重并排序。
- 指定时刻的查询和原始下载使用 `*<HHMMSS>*.h5` 通配符；这不是严格批次匹配。
- 采集原型把设备 TXT 保存为
  `RAW-HHMMSS-<device_id>-S00000.txt`，再把扩展名替换为 `.h5`。
- 采集原型从设备 `/home/data` 读取 `listdir()[0]`；文件排序和完成标志尚未定义。

## 4. 当前调用链及输入、输出、副作用和异常

### 4.1 GUI 采集按钮

```text
startButton
→ interval_comboBox 提取数字分钟
→ 注册表按钮规格 + 当前静态控件收集选中设备
→ 设置本地 GUI 文件锁/JSON 状态
→ 设置 EPICS_CA_ADDR_LIST
→ 读取 AC-LA-INJ1-TIM:WRN1:MCFQ8
→ 生成 legacy 消息
→ send_start()
```

| 步骤 | 输入 | 输出 | 副作用 | 当前异常表现 |
|---|---|---|---|---|
| 时长 | 组合框文本 | 只保留数字的字符串 `interval` | `lock_duration=interval*60` | 无数字时 `int()` 抛异常 |
| 设备选择 | 47 条按钮规格、实际存在的 Qt 控件 | 按注册表顺序排列的选中 ID 列表 | 无 | 缺控件只打印列表；该设备不能被选中 |
| 锁 | Linux 锁文件、状态 JSON | 布尔获取结果、剩余秒数 | 创建/覆盖状态文件，改变按钮状态 | 异常打印中文错误并返回 `False`；锁失败后当前回调仍继续读取 EPICS/发送 |
| EPICS 频率 | 固定 CA 地址和频率 PV | `frequency` | 设置进程环境变量，连接 EPICS | 连接/读取异常未在本回调中结构化处理 |
| legacy 消息 | 频率、分钟字符串、设备列表 | Python 字符串 | 无 | 当前格式必须保持不变 |
| `send_start` | host、端口 5000、字符串 | UTF-8 响应或 `False` | 建立 DEALER socket，以本机 IP 为 identity，最多等待 3 秒 | 任意异常折叠为 `False`；GUI 外层打印 `something wrong in connecting serve` |

当前 legacy 消息表达式为：

```python
f"{frequency},{interval},{selected_devices}"
```

脱敏示例：

```text
100,10,['AC_LA_INJ1_BI_SBPM08', 'AC_LA_BC1_BI_SBPM02']
```

其中时长字段当前来自 GUI 的“分钟数文本”，不是候选协议中的明确秒数。不要在阶段 0
修正或重新解释这一语义。

### 4.3 GUI 对齐


- 输入：远程目录、`runID`、`HHMMSS`、当前 47 台设备顺序。
- 输出：`AlignmentResult`。
- 副作用：SSH/SFTP 下载到临时文件；当前仍在 GUI 主线程执行。
- 异常：
  - 文件名不匹配正则时忽略该文件，并保持后续文件与设备不发生位置偏移；

```text

```

- 导出输出：
  - legacy：`YYYYMMDD_HHMMSS_BPMdata.h5`
  - v2：`YYYYMMDD_HHMMSS_BPMdata_v2.h5`

### 4.5 采集原型

```text
ZMQ PULL 单条整数频率
→ 读取 acquisition_pv_list.txt
→ EPICS 0 → 1，等待 5 秒，再写 0
→ 最多 17 个 SSH/SFTP 任务
→ /home/data/listdir()[0]
→ RAW-HHMMSS-device-S00000.txt
→ 三列 TXT 解析和 X/Y / 1000
→ 单 BPM HDF5
```

- 输入：整数频率、`duration_seconds.txt`、12 台采集清单、环境变量中的设备 SSH 信息。
- 输出：本地 `WAVEFORM_LOCAL_DATA_ROOT/YYYYMMDD/raw/BIData/` 下 TXT/HDF5。
- 副作用：绑定 ZMQ 5000、执行 EPICS 写、连接每台设备 SSH、创建目录和文件。
- 异常：
  - 非整数消息在 `int()` 处失败；
  - 不支持频率只打印 `something wrong`，循环仍可能继续；
  - SSH 失败多被折叠为 `wrong<host>`；
  - 空目录或首文件不合适会失败或选错文件；
  - TXT 非三列行被静默跳过；
  - 仍固定写 1024 点，没有先验证有效行数；
  - 时长使用 `YYYYMMDDHHMMSS` 整数相减，跨分钟/小时/日期语义错误。

该原型不在阶段 0 运行，不得对其执行 EPICS、ZMQ 或 SSH 集成测试。

## 5. 数据结构契约

### 5.1 单 BPM HDF5

已验证 reader 接受：

- 根 dataset `BunchIDData`：整数，形状 `(1, N)` 或 `(N,)`，读出后为 `uint64`；
- 根 dataset `Data`：形状 `(2, N)`；
- `Data[0, :]` 为 X，`Data[1, :]` 为 Y；
- 根属性 `Device` 非空；
- 线上已观察样例为 `N=1024`、`BunchIDData uint64`、`Data int64`。

采集原型 writer 当前固定：

- `BunchIDData (1,1024) uint64`；
- `Data (2,1024) int32`；
- 根属性 `Device`、`Data_0=bpm_x`、`Data_1=bpm_y`。

X/Y 除以 1000 后的物理单位、scale 和 1024 点是否为正式不变量尚未确认。

### 5.2 legacy 合并 HDF5

- `BunchIDData`：`(1,N)`，当前适配器保证 `uint64`；
- `Data`：`(2*D,N)`，设备 `i` 的 X/Y 分别位于 `2*i`、`2*i+1` 行；
- 根属性 `Device`：长度为 `D` 的设备列表；
- 根属性 `Data[0:]_<i>=<device>_X`、
  `Data[1:]_<i>=<device>_Y`；
- 没有 `valid_mask`，因此含缺失单元的结果不能写为 legacy；
- 旧 `create_hdf5()`、`save_newfile()` 等包装仍保留供兼容，不要求后续新代码使用。

### 5.3 HDF5 v2

- 根属性：
  - `schema_name=site-user-waveform-alignment`
  - `schema_version=2`
  - `created_utc`
  - `parameters_json`
  - `metadata_json`
- datasets：
  - `bunch_ids uint64`
  - `x`
  - `y`
  - `valid_mask bool`
  - `device_ids`
  - `skipped_devices_json`
  - `quality_report_json`
- `x`、`y`、`valid_mask` 形状都必须是 `(D,N)`。
- GUI 导出 metadata 当前包含 `run_id` 和 `time_sec`。

### 5.4 `AlignmentResult`

| 字段 | 当前契约 |
|---|---|
| `bunch_ids` | 一维 `np.uint64` |
| `device_ids` | 稳定排序、非空且无重复的 tuple |
| `x`, `y` | 与 `(设备数, bunchID 数)` 一致的二维数组 |
| `valid_mask` | 同 shape 的 bool 数组；False 对应的 X/Y 零只是占位 |
| `skipped_devices` | `device_id`、`reason`、`detail` |
| `quality_report` | 每设备数量、零/重复、原顺序、步长和原因 |
| `parameters` | 本次 strict/coverage 与质量策略 |

默认参数为：

```text
mode=strict
min_id_device_coverage=1.0
min_device_id_coverage=1.0
zero_policy=keep
duplicate_policy=reject_device
```

GUI `main_alignment_process()` 当前显式使用 strict 默认。coverage 的两个阈值、不同
bunchID 时基、零 ID 的现场含义和 50% legacy 跳过规则均未得到现场业务确认。阶段 0
不决定这些规则。

## 7. 锁和任务状态来源

当前 GUI 锁来自两个本地 Linux 文件：

```text
/home/site-user/waveform_data/lock/button_lock.lock
/home/site-user/waveform_data/lock/lock_status.json
```

- `fcntl` 写锁用于进程互斥；
- JSON 保存 `is_locked`、ISO `start_time`、`duration` 和 `last_save`；
- 默认 600 秒，点击采集后改为组合框分钟数乘 60；
- QTimer 每秒根据本地时间更新按钮；
- 关闭窗口只关闭当前 fd，不写“任务结束”；
- 本地锁状态不等于生产采集任务状态。

候选 JSON 协议另有 `accepted → running → succeeded/failed/cancelled` 与 `rejected` 状态，
但它尚未替换 GUI 文件锁，也没有接入生产服务端。

- 改变 `/SHINE_Data/AC/LA/YYYYMMDD/raw/BIData/` 或
  `RAW-HHMMSS-device-Sxxxxx.h5` 的解析；
- 改变单 BPM、legacy 合并或 v2 HDF5 schema/dtype/设备行映射；
- 删除 legacy 导出或让含缺失结果静默写成 legacy；
- 改变 bunchID 的 `uint64`、strict 交集、coverage 或不同步长处理；
- 猜测并转换不同 bunchID 时基；
- 改变 `fcntl`/状态 JSON 的锁语义；
- 把候选 JSON 直接发送到生产；
- 触发 EPICS/BPM、修改生产程序/清单或 `/SHINE_Data`。

### 中风险

- 移动 `overlap.py` 函数或删除兼容包装；
- 改变 `main.py`、`overlap.py` 或 `waveform_storage` 的导入路径；
- 修改缓存键或缓存失效时机；
- 修改注册表、远程文件或对齐结果的设备排序；
- 修改按钮对象名或回调映射；
- 改变未知设备、坏文件和无交集的异常/跳过表现；
- 改变导出文件名和 `auto` 选择条件。

### 低风险

- 增加纯函数或 mock/fake 离线测试；
- 增加行为契约和风险文档；
- 增加只读诊断；
- 在不改变外部入口的前提下增加兼容包装层；
- 补充静态检查和测试说明。

风险等级不等于授权。任何阶段都必须继续遵守生产安全边界。

## 11. 后续重构禁止改变的行为

在业务规则得到确认并有显式迁移方案前，阶段 1 及以后必须：

1. 保留七个当前按钮对象名到业务动作的映射或提供等价兼容层；
2. 保持 legacy 采集字符串精确兼容；
3. 保持日期、时刻、远程目录、文件名和导出文件名规则；
4. 保持缓存键的四个查询维度；
5. 保持文件路径与设备 ID 成对，单文件失败不能移动后续映射；
6. 保持 `AlignmentResult` 字段、`uint64` bunchID 和 `valid_mask` 语义；
7. 保持完整结果可导出 legacy、缺失结果自动导出 v2；
8. 保留 legacy HDF5 reader/writer 与旧 GUI 包装入口；
9. 保持未知设备、读失败、无交集都有可诊断结果；
10. 不把本地候选协议、coverage 阈值或时基转换当作已确认生产规则；
11. 不把离线/静态验证表述成 GUI 点击流或现场验证。

若后续确需改变上述任一行为，应先增加新旧对比 fixture、写明迁移和回滚方案，并取得用户
及现场业务确认。
