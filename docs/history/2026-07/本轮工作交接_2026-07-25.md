## 3. 本轮完成的实现

### 3.1 对齐纯处理模块

新增 `src/waveform_storage/processing/alignment.py`：

- 输入为带设备 ID 的 `DeviceSeries`；
- 输出统一的 `AlignmentResult`；
- 支持 `strict` 和迭代 `coverage` 两种模式；
- bunchID 始终保留为 `uint64`；
- X/Y 的真实零值与缺失位置通过 `valid_mask` 区分；
- 输入乱序会与 X/Y 一起稳定排序；
- 重复 ID、长度不一致、空输入、无交集和冲突簇都有明确结果或跳过原因；
- 设备结果按 `device_id` 稳定排序，不依赖输入顺序；
- 已用 200 台合成设备验证规模和顺序无关性。

后续窗口已完成最小 GUI 接入：

- 确认、绘图和导出按查询键共享一个 `AlignmentResult`；
- strict 完整结果默认保持 legacy 导出，coverage 缺失结果默认写 v2；
- 绘图按 `valid_mask` 过滤缺失值，真实 0 保留；
- 旧 GUI 处理函数仍保留，没有重写 UI、动态设备模型或后台任务。

尚未完成：

- 未完成 GUI 点击流或 Linux 运行验证；
- coverage 阈值尚未得到现场业务确认；
- 不同 bunchID 时基的物理含义仍未知。

### 3.2 HDF5 v2 与旧格式兼容

新增 `src/waveform_storage/io/hdf5_io.py`：

- `read_single_device_hdf5()` 校验真实单 BPM 文件形状并保留 `uint64`；
- `write_alignment_v2()` / `read_alignment_v2()` 完成版本化 round-trip；
- v2 保存 bunchID、X/Y、`valid_mask`、设备 ID、跳过原因、质量报告、参数和调用方元数据；
- v2 根属性包含 `schema_name=site-user-waveform-alignment` 和 `schema_version=2`；
- v2 写入使用同目录 `.part` 文件和原子替换；
- `write_legacy_merged_hdf5()` / `read_legacy_merged_hdf5()` 兼容旧交错 X/Y 行格式；
- legacy 格式无法表达 coverage 缺失单元时会明确拒绝写入。

同时最小修改活动旧 GUI 的 `apps/operator_gui/overlap.py:create_hdf5()`：

- 删除将约 `3.8e13` bunchID 先转换为 `int32` 的溢出路径；
- 从输入到 HDF5 始终使用 `uint64`；
- 跳过异常设备后，使用过滤后的设备列表写 `Device` 及 X/Y 行属性。
