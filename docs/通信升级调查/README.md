# 通信升级调查目录

> 用途：统一收集生产通信事实，为 legacy 协议、候选 JSON v1 和 CaptureService 的最终合流
> 提供证据。查询阶段只读，不向生产端发送测试消息，不停止进程，不修改配置。

## 查询顺序

1. [服务端与部署事实](01_服务端与部署事实.md)
2. [ZMQ 与消息协议事实](02_ZMQ与消息协议事实.md)
3. [任务、采集、文件与回滚事实](03_任务采集与回滚事实.md)
4. [脱敏证据登记表](04_脱敏证据登记表.md)
5. [实验分支实施状态](实验分支实施状态.md)

## 明天至少要带回的结果

- 正式服务端程序路径、版本或哈希、启动命令、父子进程关系；
- 5000 端口对应的进程、ZMQ socket 类型、bind/connect 方向；
- 一条成功请求、一条失败请求及其逐帧响应结构；
- 服务端如何解析频率、时长和设备列表；
- 超时、重复请求、进程重启和客户端断开时的任务行为；
- EPICS 触发、远程文件完成标志、文件命名和 HDF5 落盘顺序；
- 当前锁保护的对象、持有者、超时和恢复规则；
- 可用于测试的隔离环境、端口、设备和回滚步骤。

## 证据规则

- 优先记录命令、文件路径、行号、哈希和脱敏样例，不记录口头推断；
- 密码、token、SSH 私钥、完整账号和敏感网络拓扑不得提交 Git；
- 原始日志先保存在批准的位置，仓库只放脱敏摘要；
- 无法确认的项目写 `UNKNOWN`，不要从客户端代码反推成事实；
- 每项事实注明采集时间、主机、操作者和证据来源。
