## 边界

本候选协议解决消息格式、字段校验、请求身份和任务状态转换不可测试的问题，但不假设生产
服务端已经支持 JSON、`DEALER/ROUTER`、响应或幂等处理。

在确认生产 socket 类型、响应结构、重试语义和回滚方法之前：

- GUI 继续发送现有 legacy 复合字符串；
- 不向生产端发送本候选 JSON；
- 不替换或重启生产 `saveApp`；
- 不把本地协议测试表述为现场链路验证。

## 请求

```json
{
  "version": 1,
  "request_id": "00000000-0000-4000-8000-000000000000",
  "command": "start_capture",
  "frequency_hz": 100,
  "duration_seconds": 600,
  "devices": [
    "AC_LA_INJ1_BI_SBPM08"
  ]
}
```

校验规则：

- `request_id` 必须是规范 UUID；
- 频率必须有限且大于 0，正式支持值仍待现场确认；
- 时长必须是正整数秒；
- 设备列表非空、无重复并使用规范设备 ID；
- 缺失字段和未知字段均拒绝，避免拼写错误被静默忽略。

## 响应

```json
{
  "version": 1,
  "request_id": "00000000-0000-4000-8000-000000000000",
  "accepted": true,
  "status": "running",
  "message": "capture started",
  "error_code": null
}
```

本地候选状态：

```text
accepted -> running -> succeeded
    |           |
    +---------> failed
    +---------> cancelled

rejected 终止
```

`failed` 和 `rejected` 必须包含非空 `error_code`。终止状态不能重新进入 `running`。

## 接入条件

1. 已用本地 `inproc://` fake server 验证编码、解码、非法请求、幂等、超时和状态历史；
2. 取得生产协议的只读证据并形成差异表；
3. 明确 legacy 适配器及回滚开关；
4. 经用户确认后，先在本地 fake 链路接入 GUI；
5. 现场仍按单台、少量设备、分区逐级验证。

## 本地 fake 闭环状态

`transport/zmq_transport.py` 与 `acquisition/task.py` 只用于本地候选链路。当前覆盖：

- accepted → running → succeeded/failed/cancelled；
- 非法字段 rejected；
- 相同 request_id 返回缓存终态，不重复执行 runner；
- 部分设备失败、执行异常和显式超时；
- 当前 legacy 字符串的精确适配器。

生产 socket 类型、响应帧、幂等、取消和状态查询仍未知。GUI 当前 `send_start` 未切换到
候选 JSON，fake 结果不能表述为生产协议验证。
