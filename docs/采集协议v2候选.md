## v2 变化

v2 在 v1 的设备快照之外增加 `area_ids`，把操作员选择的束线区域作为一等字段记录。客户端
只能从区域模型生成设备列表；服务端正式实现时必须使用自己的版本化注册表重新展开
`area_ids`，并拒绝与 `devices` 快照不一致的请求。这样既能保留请求审计信息，也能避免客户端
通过删减设备形成“区域内部分选择”。

```json
{
  "version": 2,
  "request_id": "00000000-0000-4000-8000-000000000000",
  "command": "start_capture",
  "frequency_hz": 100,
  "duration_seconds": 600,
  "area_ids": ["INJ1", "BC1"],
  "devices": [
    "AC_LA_INJ1_BI_SBPM08",
    "AC_LA_BC1_BI_SBPM02"
  ]
}
```

`area_ids` 与 `devices` 都必须非空、无重复并使用规范 ID。缺失字段和未知字段均拒绝。请求仍
使用 UUID 作为幂等身份，响应状态模型仍为：

```text
accepted -> running -> succeeded
    |           |
    +---------> failed
    +---------> cancelled

rejected 终止
```

## 三种 GUI 模式

- `demo`：默认、安全、确定性离线数据；采集、检索、对齐、绘图、导出和下载均可展示。
- `legacy`：显式现场兼容模式；仍把规范请求适配为当前复合字符串，发送前二次确认。
- `candidate_v2`：显式结构化模式；必须提供独立的
  `WAVEFORM_CANDIDATE_ZMQ_ENDPOINT`，不默认指向生产地址。

三个模式共用同一套按钮和后台接口，不做失败后的自动协议回退，避免超时后重复触发采集。
