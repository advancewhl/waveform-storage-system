## v2 变化

v2 在 v1 的设备快照之外增加 `area_ids`，把操作员选择的束线区域作为一等字段记录。客户端
只能从区域模型生成设备列表；服务端使用自己的版本化部署注册表重新展开
`area_ids`，并拒绝与 `devices` 快照不一致的请求。这样既能保留请求审计信息，也能避免客户端
通过删减设备形成“区域内部分选择”。

```json
{
  "version": 2,
  "request_id": "00000000-0000-4000-8000-000000000000",
  "command": "start_capture",
  "frequency_hz": 100,
  "duration_seconds": 600,
  "area_ids": ["INJ1", "BC1"],
  "devices": [
    "AC_LA_INJ1_BI_SBPM08",
    "AC_LA_BC1_BI_SBPM02"
  ]
}
```

`area_ids` 与 `devices` 都必须非空、无重复并使用规范 ID。缺失字段和未知字段均拒绝。请求仍
使用 UUID 作为幂等身份，响应状态模型仍为：

```text
accepted -> running -> succeeded
    |           |
    +---------> failed
    +---------> cancelled

rejected 终止
```

服务端收到合法 `start_capture` 后立即返回 `accepted`，不会让 ZMQ 请求阻塞完整采集时长。
任务随后在单独线程执行，同一服务实例同时只运行一个采集任务。

服务端在 `duration_seconds` 总窗口内重复执行“EPICS 触发 → 等待 → SSH 下载 → HDF5
落盘”。当前支持 1000、500、100、50、10、5、2 Hz，等待值分别为
2、4、12、22、2100、4200、512 s。10 Hz 等待值于 2026-10-26 经现场确认；其他
频率明确拒绝，不做插值。每周期文件使用 `S00000`、`S00001`……序列号，任务状态中同时
保存全部输出路径和成功周期数。MongoDB 的文件唯一键包含 `capture_sequence`，因此同一
请求和设备的多个周期不会互相覆盖。该循环语义已离线验证，尚未完成真实设备验收。

只读控制请求：

```json
{
  "version": 2,
  "request_id": "原采集任务UUID",
  "command": "get_status"
}
```

`health` 使用同样三个字段，但 `request_id` 是本次健康查询 UUID。`cancel` 使用采集任务
UUID，在 EPICS 复位、等待或传输完成后的安全边界结束任务。相同采集 request ID 和相同
payload 返回已保存状态，不重新触发；相同 ID 配不同 payload 返回
`REQUEST_ID_CONFLICT`。服务重启时未完成任务标记为 `INTERRUPTED_BY_RESTART`，不自动重放。

## 三种 GUI 模式

- `demo`：默认、安全、确定性离线数据；采集、检索、对齐、绘图、导出和下载均可展示。
- `legacy`：显式现场兼容模式；仍把规范请求适配为当前复合字符串，发送前二次确认。
- `candidate_v2`：显式结构化模式；必须提供独立的
  `WAVEFORM_CANDIDATE_ZMQ_ENDPOINT`，不默认指向生产地址。

三个模式共用同一套按钮和后台接口，不做失败后的自动协议回退，避免超时后重复触发采集。

## MongoDB 历史查询

candidate v2 启用 MongoDB 后支持查询某天已有的采集时刻：

```json
{
  "version": 2,
  "request_id": "00000000-0000-4000-8000-000000000001",
  "command": "list_capture_times",
  "storage_date_local": "2026-08-25"
}
```

选择时刻后，GUI 按设备查询由服务端登记的 HDF5 文件：

```json
{
  "version": 2,
  "request_id": "00000000-0000-4000-8000-000000000002",
  "command": "find_waveform_files",
  "storage_date_local": "2026-08-25",
  "time_sec": "120721",
  "devices": ["AC_LA_INJ1_BI_SBPM08"]
}
```

服务端只返回 MongoDB 中已完成文件的 path；GUI 随后通过既有存储 SSH 通道读取或下载这些
精确路径，不再在 candidate v2 模式下使用 `find` 扫描整个日期目录。legacy 模式不变。
